1. VISÃO GERAL
------------------------------------------------------------------------------
App de alimentação, treino e acompanhamento físico com IA. Regras de negócio
(cálculos, limites, permissões, assinatura) controladas pelo sistema; a IA é
usada para personalização e geração de conteúdo, nunca como fonte de verdade
para regras críticas.

Repositório:   https://github.com/larissapbro-sketch/MacroFit360
Produção:      https://macrofit360.vercel.app
Banco:         Supabase (projeto rrvjqjhxkafcczqqfiqq)


------------------------------------------------------------------------------
2. STACK TÉCNICA
------------------------------------------------------------------------------
- Next.js 16 (App Router, Turbopack) + TypeScript + Tailwind CSS
- Supabase: Postgres + Auth + RLS
- IA: Anthropic Claude (modelo claude-sonnet-4-5-20250929) via @anthropic-ai/sdk,
  usando tool use para forçar resposta estruturada (JSON) validada com Zod
- Pagamentos: Stripe (Checkout + Webhooks), modo TESTE (sk_test_...)
- Gráficos: Recharts
- E-mail transacional: Resend (em configuração — ver seção 8)
- Deploy: Vercel, projeto "macrofit360", ligado ao GitHub (deploy automático
  a cada push na main)

FASE 2 — CADASTRO/ONBOARDING .............................. CONCLUÍDA
  - Onboarding: peso, altura, idade, sexo, objetivo, dias de treino,
    equipamentos, orçamento semanal
  - /perfil para edição, mesma action (upsert) do onboarding

FASE 3 — IA PLANNER ........................................ CONCLUÍDA
  - Cálculos SEM IA: TMB (Mifflin-St Jeor), TDEE por fator de atividade,
    ajuste calórico por objetivo, macros (proteína g/kg, gordura 25% cal,
    carboidrato no restante) — arquivo: lib/calculations/nutrition.ts
  - Geração de cardápio via IA: prompt construído a partir das metas
    calculadas, resposta forçada via tool use, validada em 2 camadas
    (schema Zod + regra de negócio: soma de calorias/macros dentro de
    tolerância de 20% da meta)
  - Geração de treino via IA: mesma arquitetura, valida que o nº de dias
    do plano bate exatamente com os dias disponíveis do usuário
  - Retry (até 2 tentativas) com FEEDBACK do erro da tentativa anterior
  - Nunca salva plano incompleto/inválido; log de auditoria em
    ai_generations sempre (sucesso ou falha)
  - Substituições inteligentes: usuário pode pedir troca de item (texto
    livre ou clique em alternativa sugerida), IA gera substituto dentro de
    20% de tolerância nos macros do item original
  - TESTADO com chamadas reais à API: caso real de rejeição por macro fora
    da tolerância (188g proteína vs meta 160g) levou ao ajuste de 15%→20%
    de tolerância

FASE 4 — DASHBOARD ......................................... CONCLUÍDA
  - Registro de progresso: peso, medidas (cintura/quadril/peito/braço/coxa),
    observações

  - Gráfico de evolução do peso (Recharts)
  - Comparativo semanal (adesão, treinos, metas — semana anterior vs atual)
  - Decisão de escopo registrada: gráficos de calorias/proteína consumidas

    depois (ver seção 6)

FASE 5 — PREMIUM ........................................... CONCLUÍDA

8. LIMITAÇÕES/DECISÕES DE ESCOPO REGISTRADAS (não são bugs)
------------------------------------------------------------------------------
  - Substituições e diário alimentar não têm "desfazer" granular por item
    (diário tem "zerar tudo", substituição não tem desfazer — regenerar o
    plano resolve)
  - Notificações são só in-app (sem push/e-mail) — decisão confirmada
  - Sem diário de treino "por data calendário" — workout_sessions.day é o
    número do dia dentro do plano (1..N), não uma data. A adesão semanal é
    calculada por PLANO/SEMANA, não por dia corrido
  - Limite Free é contador de gerações vitalício (não reseta mensalmente)
    — decisão consciente para não alterar a arquitetura de meal_plans/
    workout_plans de 1 template por vez
